# Draft Zero V0.1.0 最终集中复核卡（给产品所有者的一次性短测）

**为什么还需要你：** 桌面组件的"添加到桌面"、系统减少动态效果开关、VoiceOver 朗读这三件事都必须在真实系统界面上由人操作；本机自动化无法安全替代（此前合成点击三次误触你正在使用的其他应用，已停止）。整轮约 **20–25 分钟**，全部使用**隔离测试数据**，不会碰你的日常库。

**准备（2 分钟）：**

1. 确认已安装最终包 `DraftZero.app`（来自 dist ZIP；首次打开如遇 Gatekeeper 拦截，到「系统设置 → 隐私与安全性」点「仍要打开」——这正是要验证的安装体验，请顺带记录提示文案是否清晰）。
2. 终端执行隔离（复制整段）：
   ```
   launchctl setenv DZ_WORKSPACE_DIR /tmp/dz-qa/workspace
   mkdir -p /tmp/dz-qa/workspace
   open -a DraftZero
   ```
3. 应用顶栏应出现横幅「QA 隔离工作区：/tmp/dz-qa/workspace」——看到它即说明你在隔离环境（发布版已实测通过 ✅）。

## 卡 A：桌面组件（发布门槛，约 10 分钟）

1. 在桌面空白处**右键 →「编辑组件…」**（或打开通知中心 → 底部「编辑组件」）。
2. 搜索「Draft Zero」→ 应出现中号组件 → 点添加到桌面。
3. 核对四条主路径（隔离库已由 QA 数据/你刚启动的应用填充；若组件显示"还没有项目"，先在应用里建 2 个项目并把其中一个设为 TODO）：
   - a. 组件显示 **TODO 区**与**最近项目区**；
   - b. 点 TODO 行的 ✓ → 该项目变「基本完成」，回到主应用确认同步；
   - c. 点最近项目行的 ◌ → 变「TODO」；
   - d. 点「新建草稿」→ 主应用打开新稿页。
4. 空状态：`launchctl setenv DZ_WORKSPACE_DIR /tmp/dz-empty && mkdir -p /tmp/dz-empty && open -a DraftZero`，等组件刷新后应显示「还没有项目」引导文案。
5. 明暗背景：组件分别放在亮色与深色壁纸上（或切换系统外观），文字应可读。
6. **恢复**：`launchctl unsetenv DZ_WORKSPACE_DIR`，删除测试组件，重启 Draft Zero 确认日常数据未变。

**判据**：4 条主路径 + 空状态 + 明暗可读 → 通过。组件显示"无法读取工作区数据"→ 记录失败（说明扩展进程没继承到隔离环境，属测试环境问题，不是产品缺陷——日常路径已实测同库读写）。

## 卡 B：减少动态效果（约 5 分钟）

1. 记录当前状态：系统设置 → 辅助功能 → 显示 → 减少动态效果。
2. 打开开关，启动 Draft Zero，终端运行：
   ```
   log show --last 5m --predicate 'subsystem == "com.draftzero.app" AND category == "accessibility"'
   ```
   应看到 `accessibilityReduceMotion(启动读取) = true`（应用确实读到系统值）。
3. 走一遍主路径：线索台点开/关闭一条线索的证据栏（应淡入或直接出现，无横向位移）→ ⌘N 新建草稿 → ⌘L 添加链接弹层。
4. 关闭开关恢复原状，再跑一次第 2 步命令，应见 `= false`。

**判据**：第 2 步读到 true 且第 3 步无位移依赖 → 通过。

## 卡 C：VoiceOver 主路径（约 10 分钟）

1. ⌘F5 开启 VoiceOver（或系统设置 → 辅助功能 → VoiceOver）。
2. 依次听读并记录是否「不用看屏幕也能懂」：
   - VO+左右箭头沿左侧索引走一遍（01 草稿箱 → 06 设置，每项应朗读编号+名称）；
   - VO+空格激活「新草稿」→ 听到「标题」「正文」字段 → 输入两句 → 保存；
   - ⌘2 到线索台 → 逐条听队列（每条应含两稿标题与证据说明）→ 对一条执行「加入项目」→ 弹层内焦点应落在弹层、关闭后回到原处；
   - 打开项目档案 → 状态菜单改为 TODO → 回 TODO 页确认；
   - 打开刚编辑的草稿详情 → 版本来路 → 比较旧版 → 恢复；
   - Escape 返回，确认焦点不丢失。
3. ⌘F5 关闭 VoiceOver。

**判据**：全部步骤朗读可理解、焦点不困死 → 通过；任一步「听不懂」或焦点卡死 → 记录具体步骤。
