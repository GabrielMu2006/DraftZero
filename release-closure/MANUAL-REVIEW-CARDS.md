# 人工复核卡（R-012 / R-009 剩余项，2026-09-29）

本轮自动化的边界：AX 审计只能证明可检查属性（名称/角色/动作/状态），不能证明真实朗读体验；系统设置开关与桌面组件添加需要真人在系统界面上操作。以下三张卡按步骤执行后，请把结果（通过/问题描述）记录到本文件末尾或直接反馈。

## 卡 1：减少动态效果（R-012，约 5 分钟）

背景：应用代码已修复（`ClueDeskView` 证据栏在减少动态效果开启时用淡入代替横向位移；全工程无其他显式位移动画，状态信息均为静态文字/线型）；Debug 构建内置只读探针，会在日志中记录应用实际读到的系统值。

1. 记录当前状态：系统设置 → 辅助功能 → 显示 → 减少动态效果（下称"开关"）。
2. 打开开关。
3. 启动 Draft Zero（Debug 构建正常启动即可），终端运行：
   `log show --last 5m --predicate 'subsystem == "com.draftzero.app" AND category == "accessibility"'`
   应看到 `accessibilityReduceMotion(启动读取) = true`（这是本项验收的核心判据：应用确实读到系统值）。
4. 走一遍主路径并观察：线索台点开/关闭一条线索的证据栏（应为淡入或直接出现，无大幅位移）→ ⌘N 新建草稿 → ⌘L 添加链接弹层 → 项目状态修改。任何"只有靠动画才能明白"的信息都记为问题。
5. 关闭开关（恢复第 1 步原状态），再跑一次第 3 步命令，应看到 `= false`。
6. （加分）开着开关再次切换：`onChange` 探针会记录 `accessibilityReduceMotion(系统切换) = true/false`，无需重启应用。

**判据**：第 3 步读到 `true` 且第 4 步无位移依赖 → 通过。第 3 步读到 `false` → 记录失败。

## 卡 2：VoiceOver 主路径（R-012，约 15 分钟）

背景：AX 审计已通过（全部 143 个按钮/30 个 cell 有可读名称与 AXPress；本轮修复 3 处缺失名称：DeepSeek Key 输入框、新稿页标题/正文、详情页正文编辑区）。以下验证朗读体验本身。

准备：系统设置 → 辅助功能 → VoiceOver → 启用（或 ⌘F5）。建议语速默认。

按顺序走完并记录每一步的朗读是否"听得懂、不用看屏幕"：

1. **导航**：VO+左/右箭头从索引脊背走一遍（01 草稿箱 → 06 设置），每项应朗读"编号 名称 项数，当前页"。
2. **创建草稿**：VO+空格激活"新草稿" → 标题字段（朗读"标题"）→ 正文（朗读"正文"）→ 输入两句话 → VO+空格点"保存到草稿箱"。
3. **线索台**：前往线索台（⌘2），VO+右箭头逐条听队列（每条应含"线索：甲 × 乙"及证据词），选中一条后听证据（共同术语或"内容含义相近"）、来源信息。
4. **裁决**：VO+空格执行"加入项目" → 弹层中选现有项目 → 确认；再对另一条执行"不相关"与"暂缓"。注意弹层打开时焦点应落在弹层内、关闭后焦点回到触发处。
5. **项目与状态**：打开项目档案 → 听成员与演化事件列表 → 状态菜单改为 TODO → 回到 TODO 页确认。
6. **版本**：打开刚编辑过的草稿详情 → 版本来路 → 比较旧版（朗读 ± 行）→ 恢复。
7. **返回**：Escape 回到原位置，确认焦点不丢失。

**判据**：全部步骤朗读可理解、焦点不跳失/不困住 → 通过；任一步骤"朗读内容无法理解"或焦点卡死 → 记录具体步骤与现象。

## 卡 3：桌面组件实机（R-009，约 10 分钟）

背景：本轮已完成并实测**数据隔离修复**（主应用与组件扩展现在走同一个 `AppDatabase.defaultDatabaseURL()` 实现，支持 `DZ_WORKSPACE_DIR` 隔离目录）；组件的时间线 SQL、两个状态动作的写路径已用独立进程实测通过（见 [P4-widget-intents-write.txt](evidence/P4-widget-intents-write.txt)）。剩余的只有"真实桌面添加"这一步系统操作。

隔离环境（推荐，测真实动作不碰日常数据）：

1. 终端执行 `launchctl setenv DZ_WORKSPACE_DIR /tmp/dz-qa/workspace`（该目录本轮已种入：QA待办项目[基本完成]、QA最近项目[TODO]、29 份草稿；重启机器后需重种或改用任意目录正常启动一次主应用让它自建）。
2. 正常启动 Draft Zero（`open -a` 或点图标），确认草稿箱显示隔离库内容（QA 项目）。
3. 桌面空白处右键 →"编辑组件…"→ 搜索"Draft Zero" → 添加中号组件。
4. 核对四条主路径：
   a. 组件显示 TODO 区（QA最近项目）与最近项目区；
   b. 点 TODO 行的 ✓ → 该项目变"基本完成"，主应用激活后同步；
   c. 点最近项目行的 ◌ → 变 TODO；
   d. 点"新建草稿" → 主应用打开新稿页。
5. 空状态：把 `DZ_WORKSPACE_DIR` 指向一个空目录（`launchctl setenv DZ_WORKSPACE_DIR /tmp/dz-empty && mkdir -p /tmp/dz-empty && open -a Draft Zero`，组件刷新后）应显示"还没有项目"引导文案。
6. 明暗背景：组件置于亮色壁纸与深色壁纸（或切换系统外观）各看一次，文字应可读。
7. **恢复**：`launchctl unsetenv DZ_WORKSPACE_DIR`，删除测试组件，正常重启 Draft Zero 确认日常库未变。

**判据**：4 条主路径 + 空状态 + 明暗可读 → 通过；组件读不到隔离数据（显示"无法读取工作区数据"）→ 记录，那说明扩展进程未继承环境变量，需要改用发布版 App Group 方案再测。
